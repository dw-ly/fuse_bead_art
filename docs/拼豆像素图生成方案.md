# 照片 → 拼豆像素图 生成方案

> 版本：v1.0　日期：2026-08-03
> 目标：把照片转换成可以照着拼的拼豆图纸，**既能分辨出图片内容，又控制在一个合理的拼豆数量**。

---

## 一、一句话结论

照片转拼豆图，本质是**「调色板受限的颜色量化」**问题：把照片缩小到目标网格（如 39×39），再让每个格子都映射到"最接近的豆子颜色"。难点不在缩小，而在**颜色匹配的感知准确性**与**分辨率/豆量的权衡**。

调研确认：市面成熟工具（PindouAI、NetFisher、perler-beads.org 的 AI 生成器）核心参数就是两个——**图案宽度（豆数）** + **最大颜色数 / 色卡品牌**。我们的方案沿用这一设计，但增加**豆量与保真度的量化权衡**和**背景柔化**两项增值能力。

---

## 二、拼豆物理约束（决定"合理豆量"的硬边界）

### 2.1 拼豆板规格

拼豆（MIDI beads，直径 5mm）固定在方形网格板上。常见规格与参考豆量：

| 拼豆板规格 | 豆子数量 | 参考耗时 | 适合内容 |
|---|---|---|---|
| 29×29 | 841 | 2~4 小时 | 简单图形、表情、logo、像素画 |
| 39×39 | 1,521 | 4~7 小时 | 单个主体特写、简单人像 |
| 49×49 | 2,401 | 7~12 小时 | 人像、宠物脸 |
| 59×59 | 3,481 | 12~18 小时 | 高质量人像、场景 |
| 80×80+ | 6,400+ | 数天 | 精细作品、风景 |

> **来源**：perler-beads.org FAQ 明确建议——想要简单/可爱选 **29×29、58×58**；想要更细节选 **80×80 以上**；支持自由输入任意整数。国内 MARD 单板多为 29×29 / 39×39 / 49×49，更大尺寸需要多块板拼接或专用大板。
>
> ⚠️ **实施前请确认你手里的板子规格**，把它作为系统里的"最大网格"约束。

### 2.2 色号约束（已获得真实数据）

国内主流拼豆品牌的完整色号表已抓取并解析，见 [data/bead_palettes.json](../data/bead_palettes.json)：

| 品牌 | 色号数 | 色系分布 |
|---|---|---|
| **MARD 全色 291**（玛利酷，国内最主流） | 291 | 15 个色系：黄26 / 绿32 / 蓝29 / 紫26 / 粉24 / 红25 / 棕21 / 黑白灰23 / 多彩15 / 扩展23 / 荧光5 / 亮色28 / 纯白1 / 特效5 / 特别8 |
| **MARD 标准 221** | 221 | 9 个色系，全色 291 的核心子集 |
| **Artkal** | 176 | 标准159 + 扩展17 |
| **Perler**（美国主流） | 110 | 扩展色系 |
| **Hama**（丹麦主流） | 89 | 标准色系 |
| **Artkal Mini**（2.6mm 迷你豆） | 207 | 8 个色系 |

> 入门套装通常 24 色 / 48 色，属于上面大色板的一个子集。**算法上色号表做成可配置输入**即可：用大色板做初筛，再让用户勾选"我实际拥有的色号"来精调。

## 三、核心算法管线（5 步）

```
照片 → ① 主体裁剪 → ② 降噪/增强 → ③ 缩小到网格 → ④ 颜色量化到豆色 → ⑤ 输出图纸
```

### ① 主体裁剪（可选项，效果显著）

把照片裁剪成目标板的宽高比（方形板裁成正方形）。进阶版：
- **人像**：面部检测（如 OpenCV Haar / DNN）自动居中裁剪，去掉大片空白，省豆子。
- **通用**：显著性检测或简单边缘密度加权裁剪。

### ② 降噪 / 增强

- **边缘保持平滑**（bilateral filter）：压掉照片噪声，让皮肤/天空变成干净色块，避免缩小时杂色混入。
- **饱和度微调**：豆子颜色普遍不如照片鲜艳，转换前略微提升饱和度，成品更"像拼豆"。

### ③ 缩小到网格（关键）

- 缩到目标分辨率（如 39×39）必须用**面积平均（area / lanczos）**，不能用最近邻——否则每个格子的颜色是"抽样式"的，失真大。
- 每格颜色 = 原图局部区域均值，才有"像"可言。

### ④ 颜色量化（最关键）

把每个格子颜色映射到最近的豆色。**技术要点**：

> ❌ 在 RGB 空间算"最近颜色"是错的——人眼感知与 RGB 欧氏距离不一致。
> ✅ 先把 RGB 转成 **CIELAB**，用 **ΔE76（或 ΔE2000）色差**判断最近色，结果符合人眼直觉。

两种策略：

- **方案 A（简单，适合插画/logo）**：每格直接找 LAB 距离最近的豆色。O(格子数 × 色号数)，快。
- **方案 B（推荐给照片）**：先对缩小图做 **k-means 聚类**得到 12~24 个主色，每个主色再映射到最近豆色。照片的色调个性被保留，不会因为"离哪颗豆都差一点"而发灰发脏。**照片用方案 B，效果差距明显。**

### ⑤ 输出图纸

- **网格施工图**：每格填豆色色块 + 色号编号。
- **各色用量统计清单**：每种颜色需要几颗豆，方便配豆、对账。
- 可导出 PNG（预览/分享）/ PDF（打印对照）。

## 四、分辨率 vs 保真度（核心权衡）

"能分辨出内容"和"豆子数量合理"是一对矛盾。用两条规则解决：

### 4.1 经验法则（按主体）

| 主体 | 人脸能认出 | 眼睛能"读"出 | 建议最小网格 |
|---|---|---|---|
| 脸特写 | 脸宽需 10~15 颗豆 | 需 2~3 颗豆 | **49×49** |
| 全身像 / 宠物 | 轮廓 + 色块识别 | — | **39×39** |
| 简单图案 / 像素画 | 靠形状 | — | **29×29** |
| 风景 / 复杂场景 | 需更多细节 | — | **59×59+** |

### 4.2 量化准则（自动建议分辨率）

- 定义**平均每豆色差** `avgΔE` = 所有格子映射前后颜色差（LAB）的平均。
- 阈值经验：`avgΔE > 15~20` 表示失真大到不该选这个分辨率。
- 工具行为：**同一张图跑 29/39/49/59 四档，分别报告豆量与 avgΔE，让用户直观权衡**。这就是把"合理数量"从感觉变成数据。

## 五、针对照片的进阶技巧（区分普通工具和好工具）

1. **背景柔化（强烈推荐，性价比最高）**：人像/宠物照先对背景做高斯模糊（模拟景深），再缩小。背景变成几块纯色大色块 → 同样的豆量下，主体分到更多格子 → **同一块板，主体清晰度大幅提升**。
2. **边缘锐化**：量化后加一点锐化，让边缘利落，更有像素画质感。
3. **抖动（dithering）不要用**：普通像素图靠抖动补色，但拼豆每颗豆都是物理色块，抖动只会变成噪点，效果差。

## 六、现有工具对比

| 工具 | 优点 | 缺点 |
|---|---|---|
| PindouAI（国内） | 免费、内置 Perler/Hama/MARD 色板、出用量统计 | 分辨率/豆量不透明、无法限定"我实际拥有的色号" |
| NetFisher Perler 生成器 | 支持自定义宽度和最大颜色数 | 免费在线版功能偏简单 |
| perler-beads.org AI 生成器 | 主体提取→风格化→像素化→图纸，流程最完整 | 国内访问不便，无法定制色板 |
| **本项目（自研）** | **色号表可配置成自己实际拥有的颜色**；输出豆量 vs 保真度曲线；可加背景柔化 | 需要自己开发 |

自研核心价值：**① 色号表匹配你的实物豆；② 分辨率/豆量完全透明可控；③ 可加照片增强技巧。**

## 七、技术选型与实现路线

### 7.1 技术栈

| 用途 | 库 |
|---|---|
| 图像读写 / 缩放 | Pillow（area/lanczos 重采样） |
| 边缘保持平滑 / 锐化 / 模糊 | OpenCV（bilateralFilter、GaussianBlur、unsharpMask） |
| k-means 主色聚类 | scikit-learn（或自写，约 30 行） |
| RGB→LAB、ΔE | 自写（各约 15 行），不依赖重库 |

### 7.2 实现路线（分 3 步）

- **M1 最小可用原型（✅ 已完成）**：`scripts/photo2beads.py`（纯 Pillow + numpy，约 300 行）。读图 → 居中裁方 → LANCZOS 缩到 N×N → 用 MARD 291 色板 CIELAB ΔE 量化 → 输出圆角豆粒预览图 + 带色号标注/坐标刻度的施工图 + 用量 CSV。支持方案 A（nearest）与方案 B（k-means 主色聚类）、色号子集筛选（`--only`）、预览图色号标注（`-L`）。**网格上限可配置**（`--max-grid`，默认 60、物理上限 100）：细节密集的小尺寸图（如 130px 插画，狗眼鼻在 60×60 下会碎成噪点糊在一起）需 80~100 才能干净分离特征（实测 60→69 碎块、80→24、100→15）。
  ```bash
  python scripts/photo2beads.py 照片.jpg -N 60                 # 默认 MARD291 + kmeans
  python scripts/photo2beads.py 照片.jpg -N 39 -p hama -m nearest
  python scripts/photo2beads.py 照片.jpg -N 49 -k 20 --only A1,B2,F3 -o 我的图纸
  python scripts/photo2beads.py 照片.jpg -N 80 --max-grid 100  # 小图细节密时放宽上限
  ```
  示例输出见 `examples/`（60×60 演示）。
- **M1.5 前端 UI（✅ 已完成）**：`ui/pindou.html`——**纯浏览器本地运行，图片不上传服务器**，双击 `pindou.html` 即可用。拖拽上传照片 → 选网格/色板/量化方式/色号子集 → 生成成品预览 + 带色号施工图 + 配豆用量表，可一键下载 PNG/CSV。算法（`ui/core.js`）与 Python 版同源，**nearest 结果与 Python 逐格一致（已用 node + 无头 Edge 验证）**。
- **M2 参数化 + 权衡（待做）**：四档分辨率（29/39/49/60）并排输出豆量/avgΔE 对比图。
- **M3 照片增强（✅ 完成，Python + 浏览器 UI）**：按主题预设自动处理，`--preset`（CLI）/ 主题预设下拉（UI）：
  - **背景柔化**（边缘感知：主体保持锐利，背景压成大片纯色）——花/人像/动物
  - **主体质心定位**（边缘显著性质心，对口罩/角度免疫）——浏览器端默认方式
  - **人脸居中裁剪**（OpenCV Haar，脸/短边≥0.08 且与主体质心一致才采用，否则回退质心；脸占比自适应 0.3~0.6）
  - **人像转插画**卡通化（双边压平 + 颜色分级 + 勾轮廓线）
  - **像素级后处理**（CLI `--clean/--outline`，UI ④后处理区）：去孤立杂点（清掉量化噪点）、卡通描边（沿明暗边界把格子涂成色板最深色，形成轮廓线——人物可勾勒边框生成卡通形象）
  - 饱和/锐化/降噪按预设自动调整
  - 已验证：花照背景压成统一色块、用色 19→17；大脸特写触发人脸裁剪、带口罩/远景人像正确回退质心居中。依赖 `opencv-python-headless<5`（4.x 才带级联 API）。

### 7.3 关键参数默认值

| 参数 | 默认值 | 说明 |
|---|---|---|
| 色板 | MARD 291 | 可换 Hama/Perler/Artkal 或自定义子集 |
| 分辨率 | 29 / 39 / 49 / 59 四档并排 | 用户自选，默认建议 49（人像） |
| 量化方式 | 方案 B（k-means → 12~24 主色） | 扁平图可切方案 A |
| 失真阈值 | avgΔE ≤ 15 | 超过则提示加大分辨率 |
| 背景柔化 | 开启（人像/宠物） | 可关闭 |

每张照片一个主题分类文件夹，其下每张照片再一个子文件夹，输出文件自动落位（`-o` 会自动创建目录）：

```
examples/
└── 花/                      ← 主题分类（按照片内容）
    └── DSCF3505/            ← 单张照片
        ├── DSCF3505.JPG          （原图）
        ├── DSCF3505_60_preview.png （豆粒预览）
        ├── DSCF3505_60_spec.png   （施工图）
        ├── DSCF3505_60_usage.csv  （用量清单）
        └── DSCF3505_60_compare.png（原图vs图纸对比）
```

新照片跑法：
```bash
python scripts/photo2beads.py 照片.JPG -N 60 -k 32 -o examples/花/DSCF3506/DSCF3506_60
```
